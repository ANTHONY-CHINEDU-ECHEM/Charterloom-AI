# Definition of Ready and Definition of Done

## Definition of ready
A definition of ready lists the conditions an item must meet before a team commits to it. It reduces rework caused by unclear requirements and is most valuable when requirements are volatile or several teams depend on each other.

Typical ready criteria:
* A clear statement of user value.
* Acceptance criteria that can be tested.
* An estimate agreed by the team.
* Dependencies identified, with owners.
* Designs or data needed to start are available.

In workflow terms, the definition of ready becomes a checklist guard on transitions out of the intake or backlog state.

## Definition of done
A definition of done lists the conditions an increment must meet to be considered complete. It protects quality and makes progress honest.

Typical done criteria:
* Code reviewed by someone other than the author.
* Automated tests written and passing.
* Deployed to a production like environment.
* Documentation and release notes updated.
* Accessibility and security checks passed where relevant.
* Product owner acceptance recorded.

In workflow terms, the definition of done is enforced through guards on review, verification and release transitions.

## Keeping them alive
Review both definitions in retrospectives. Add criteria when escaped defects reveal gaps; remove criteria that no longer add value. Overlong definitions encourage box ticking.
